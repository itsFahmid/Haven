Architectural Overview

Introduction to Data Flow Diagrams

System Dynamics

Dynamic System Representation

A Data Flow Diagram (DFD) is a graphical representation of how data moves through a system — the external entities that supply or receive data, the processes that transform that data, the data stores where information is held, and the data flows that connect them.

Complementing the ERD (Report 02)

While the ERD modeled the static structure of Haven's 13-entity database, the DFD models the dynamic movement and lifecycle of information — essential for understanding real-time crisis triage, content delivery, anonymous consultations, and automated safety workflows.

Context Diagram

Standard Modeling Elements

Notation Used

Gane & Sarson / Yourdon Standards
External Entity

External Entity

Solid rectangle. A person or system outside Haven's boundary that supplies or consumes data — e.g. Guest / User, Verified Professional, Admin, or External AI Provider (Google Gemini API).

1.0

Process

Circle / Bubble. An activity that transforms incoming data into outgoing data. Each process is numbered (e.g. 1.0, 5.2) to designate its position in the functional hierarchy.

D# STORE

Data Store (D#)

Open-ended rectangle labelled D#. A repository where data is held for later use, corresponding directly to tables in the Haven database schema (e.g., D1 Users, D7 AI Logs).

Payload Data

Data Flow

Labelled directional arrow. Represents the movement of a specific piece of data or event trigger between an entity, a process, and/or a data store.

Boundary Actors

Description — External Entities

5 Core Entities

Guest / Anonymous User

Accesses emergency hotline contacts, psychoeducational articles, and instant crisis advice anonymously without mandatory registration. Can trigger the panic quick-exit screen mask immediately.

Registered User (Parent / Youth)

Manages personal profiles, tracks self-paced digital safety course progress, books confidential appointments with licensed clinicians, and submits peer discussions under randomized aliases.

Verified Professional

Uploads clinical credentials for admin verification, sets consultation availability, conducts confidential appointments, and handles escalated live crisis hotline cases.

Admin & External AI Provider

Admin: Verifies clinicians, moderates community content, monitors system health.
External AI Provider (Gemini API): Evaluates natural language queries, scores crisis risk severity, and returns grounded safety advice.

Group 06 – HAVEN Slide 12
Process 5.0 Pipeline

Description of Sub-Processes

5 Architectural Steps
5.1

Clean / Masked Text

Reads user/guest query (Bangla/English), strips identifiable personal data (PII), and forwards masked sanitized text to Process 5.2.

5.2

Retrieve Safety Context

Extracts validated domain rules from D4 Catalog and hotline metadata from D5 Emergency to assemble an augmented prompt.

5.3

Execute AI Guidance

Dispatches augmented prompt to External AI Provider (Gemini API); receives structured safety guidance and numerical risk classification scores.

5.4

Perform Risk Triage

Evaluates risk score. If acute crisis is detected, dispatches emergency triggers to Emergency Hotline / NGO Gateway; otherwise routes safe guidance to 5.5.

5.5

Audit & Log Interaction

Writes prompt, response, tokens, and risk telemetry to D7 AI Logs while delivering final, compassionate safety guidance with relevant emergency hotlines to the User / Guest.

Synthesis

Summary & Key Takeaways

Architectural Completeness
LEVEL 0

Single Central Process

A single platform boundary exchanging vital crisis, consultation, learning, and governance data across five external actors (Guest, User, Clinician, Admin, and External AI).

LEVEL 1

Eight Distinct Subsystems

Eight modular subsystems and nine primary data stores map directly to Haven’s 13-entity database, bridging static structure to real-time execution.

LEVEL 2

Safety-Critical Decomposition

Process 5.0 safely handles AI guidance with automated PII masking, grounded domain rule retrieval, automated risk triage escalation, and tamper-proof telemetry.

TOGETHER

Complementary DFD Hierarchy

Level 0 through Level 2 DFDs thoroughly demonstrate how Haven protects sensitive user identities while delivering instantaneous, reliable crisis intervention.
